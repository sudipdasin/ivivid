# Global self-updating distribution blueprint — 2026-11-26

All locally installable releases must support automatic repository release discovery, in-app check and configurable automatic download/install. Match OS, architecture, package format and Community/Pro edition; isolate stable and beta channels. Publish signed release manifests and SHA-256 checksums together with independently verified assets. Verify authenticity using a pinned trusted key, reject downgrades, preserve settings and user data, stage updates atomically, use native package management and OS-authorized elevation, and support rollback. Never embed credentials or execute untrusted release scripts. Test offline behavior, tampering, interruptions, previous-version upgrades and rollback before release. Existing installations require migration to an updater-equipped version. No GitHub Actions or CircleCI without owner approval.

Current iVivid implementation is discovery-only: reads public GitHub release metadata and selects newer amd64 DEB or ZIP with a checksum asset. Presence of a checksum is not signature or content verification. No installer is downloaded or executed. Full authenticated automatic installation and rollback are release blockers for claiming compliance.

## Authentication milestone

`python3 scripts/test_release_auth.py` exercises the isolated verifier with ephemeral RSA keys. `verify_package` validates the detached SHA-256 signature over exact manifest bytes, repository/tag/architecture identity, asset name, declared length and SHA-256 digest. It requires a caller-supplied independently pinned public key and private staging directory. A downloaded key is never a trust anchor. The JSON manifest has schema 1 and fields repository, tag, architecture, assets; each asset has size and sha256. The production signing key, trusted public-key distribution, signing/publishing integration, authenticated download, installer and rollback are still required. Do not execute any package based on discovery or unsigned SHA256SUMS alone. This module is not yet wired into the updater UI.

## Release signing and roundtrip gate

After independent artifact verification, use `python3 scripts/release_sign.py --tag v2.6.0-beta.1 --artifacts /path/to/verified-artifacts --key /secure/external/private.pem --output /path/to/new-metadata-directory`. Use an owner-controlled production key outside the repository and independently distribute the pinned public key. Publish manifest.json and manifest.sig with the exact verified packages. The signer does not certify that an artifact was built or tested. Run `python3 scripts/test_signed_roundtrip.py` to check signing and verification together with disposable test keys. This suite also runs under CTest. Production trust provisioning, secure download, installation and rollback remain outstanding. Never publish test keys or fixture packages.
